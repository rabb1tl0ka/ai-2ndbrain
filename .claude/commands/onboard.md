Set up this personal 2nd brain. Collects your identity and focus, writes `config.yaml`, replaces placeholders in the vault, and optionally connects Google Drive and Slack as data sources.

Run this once from the repo root before anything else.

---

## Step 1 — Check existing config

Read `config.yaml` if it exists.

- If it exists and has real values (no placeholder defaults like `"Your Name"`), show a summary and ask:
  > "A config already exists. Update it, or proceed with current values?
  > (u) Update — I'll ask you each field again
  > (p) Proceed — apply the existing config as-is
  > (s) Skip — skip creating the config"

  If the user chooses proceed, jump to Step 3.
  If the user chooses skip, jump to Step 5.

- If it doesn't exist, continue to Step 2.

---

## Step 2 — Collect config values

Ask each field below in order, one at a time. Show the field name, a one-line explanation, and an example. Wait for the answer before moving on.

1. **USER_NAME**
   > "Your full name — used throughout the vault.
   > (e.g. `Bruno Costa`)"

2. **USER_HANDLE**
   > "Your @handle for notes and attributions.
   > (e.g. `@bruno`)"

3. **USER_ROLE**
   > "Your current job title.
   > (e.g. `Engineering Manager`, `ML Lead`)"

4. **USER_COMPANY**
   > "Your company or org.
   > (e.g. `Loka`)"

5. **USER_CONTEXT**
   > "1-2 sentences describing your work context — helps Claude tailor its answers.
   > (e.g. `I lead a team of ML engineers at a consultancy. Most of my work is at the intersection of people management and technical delivery.`)"

6. **VAULT_FOCUS**
   > "What this vault is for — one short phrase.
   > (e.g. `work at Loka`, `personal knowledge`, `freelance projects`)"

---

## Step 3 — Write config.yaml

Write `config.yaml` at the repo root:

```yaml
# 2nd Brain — Personal Config
# Generated by /onboard — edit directly to update values.

USER_NAME: "<value>"
USER_HANDLE: "<value>"
USER_ROLE: "<value>"
USER_COMPANY: "<value>"
USER_CONTEXT: "<value>"
VAULT_FOCUS: "<value>"
DRIVE_FOLDERS: ""
SLACK_CHANNELS: ""
```

Leave `DRIVE_FOLDERS` and `SLACK_CHANNELS` empty for now — Step 4 handles them.

Confirm: "Config written to config.yaml."

---

## Step 4 — Replace placeholders in vault

Run this for each config field (except DRIVE_FOLDERS and SLACK_CHANNELS) where the value is not empty:

```bash
find . -path ./.kernel -prune -o -path ./.git -prune -o -name "*.md" -print0 \
  | xargs -0 sed -i "s|{{KEY}}|VALUE|g"
```

Skip `README.md` at the root.

After all replacements, verify no placeholders remain:

```bash
grep -r "{{KEY}}" . --include="*.md" --exclude-dir=.kernel --exclude-dir=.git -l
```

If any placeholder is still found, report it as a warning.

Report: "Placeholders replaced across the vault."

---

## Step 5 — Connect integrations (optional)

Ask:
> "Want to connect Google Drive and Slack so /bootstrap can pull data into your inbox?
> (y) Yes — I'll ask for folder URLs and channel names
> (n) No — skip for now, you can add them later by editing config.yaml"

If no, skip to Step 6.

If yes:

**DRIVE_FOLDERS:**
> "Google Drive folder URL(s) — comma-separated if you have multiple.
> These are the folders /bootstrap will pull from (e.g. meeting notes, project docs).
> (e.g. `https://drive.google.com/drive/folders/abc123`)
> Press enter to skip."

**SLACK_CHANNELS:**
> "Slack channel(s) to pull from — comma-separated with # prefix.
> (e.g. `#general, #my-team`)
> Press enter to skip."

Update `config.yaml` with the collected values.

---

## Step 6 — Wrap up

Print:

```
Onboarding complete.

✓  config.yaml written
✓  Vault placeholders replaced
[✓  Drive folders configured  |  ⚠  Drive not configured — edit config.yaml to add DRIVE_FOLDERS]
[✓  Slack channels configured |  ⚠  Slack not configured — edit config.yaml to add SLACK_CHANNELS]

Next: run /bootstrap to pull data from Drive and Slack into your inbox.
(Skip if you haven't configured integrations yet.)
```
